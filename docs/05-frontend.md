# 05 · หน้าเว็บ Next.js และ Design Tokens (พาสเทลกระจก)

**สถานะ:** ยืนยันแล้ว 2 ต.ค. 2026
**อ่านก่อน:** `docs/00-overview.md`
**แบบหน้าจอ:** https://claude.ai/artifact/3ZfLbyBdBdGCSA7vGzQSJo (8 อาร์ตบอร์ด) — ใช้เป็นภาพอ้างอิง **ห้ามคัดลอก HTML จากแบบ** ให้สร้างด้วย component ของโปรเจกต์ตามไฟล์นี้

## 0. วิธีใช้ไฟล์นี้

- ทำตามลำดับใน §9 จบแต่ละขั้นให้หยุด สรุป อธิบายเป็นภาษาไทย แล้วรอยืนยัน
- กติกาธุรกิจทั้งหมดอยู่ที่ Go หน้าเว็บตรวจได้เพื่อ UX เท่านั้น **ห้ามคำนวณกติกาเองแล้วตัดสินแทนเซิร์ฟเวอร์** (เช่น deadline, ที่นั่ง, สิทธิ์)

---

## 1. ข้อเท็จจริงของ Next.js 16 ที่ต้องทำตาม

ตรวจแล้วเมื่อ ต.ค. 2026 ให้ยืนยันกับเอกสารของเวอร์ชันที่ติดตั้งจริงอีกครั้ง

- `cookies()`, `headers()`, `params`, `searchParams` เป็น async ต้อง `await` ทุกครั้ง (การเข้าถึงแบบ sync ถูกถอดออกแล้ว)
- `middleware.ts` เปลี่ยนชื่อเป็น `proxy.ts` — **โปรเจกต์นี้ไม่สร้างไฟล์นี้** เพราะเมื่อมี proxy Next.js จะ buffer body สูงสุด 10 MB และส่งต่อแค่บางส่วนเมื่อเกินโดยไม่แจ้ง error ซึ่งทำให้ multipart เสียแบบเงียบ
- ต้องใช้ Node.js 20.9 ขึ้นไป · Turbopack เป็นค่าเริ่มต้น
- คำสั่ง `next lint` ไม่มีแล้ว ให้ script `lint` เรียก ESLint ตรง

## 2. สถาปัตยกรรม

| เรื่อง | การตัดสินใจ |
|---|---|
| อ่านข้อมูล | Server Component เรียก Go ตรงที่ `API_ORIGIN` ผ่าน `lib/api-server.ts` (มี `import 'server-only'`) ส่งต่อ cookie ด้วย `await cookies()` และใช้ `cache: 'no-store'` เสมอ |
| ส่งข้อมูล | Client Component เรียก `fetch('/api/...')` แบบ same-origin ผ่าน rewrite แล้ว `router.refresh()` · **ไม่ใช้ Server Actions** |
| Rewrite | `next.config` : `/api/:path*` → `${API_ORIGIN}/api/:path*` |
| หน้าที่ต้อง login | Server Component เรียก `/api/me` ถ้า 401 ให้ `redirect('/api/auth/login?return_to=' + path)` · เป็น UX เท่านั้น |
| เจ้าของร้าน | หน้าจัดการร้านเช็ค `is_owner` จากรายละเอียดร้าน ถ้าไม่ใช่ให้ `notFound()` · สิทธิ์จริงตัดสินที่ Go |
| Login / Logout | ปุ่ม login เป็นลิงก์ `<a href="/api/auth/login?return_to=…">` (เปลี่ยนหน้าเต็ม) · logout เป็น `<form method="POST" action="/api/auth/logout">` |
| State | ไม่ใช้ไลบรารี state หรือ data fetching |
| รูป | `<img>` ธรรมดาชี้ `/api/restaurants/{id}/images/{imageId}` ใส่ `width`/`height` หรือ `aspect-ratio` กัน layout เลื่อน (ปิด lint rule `no-img-element` เฉพาะจุดพร้อมเหตุผล) |
| ฟอนต์ | `next/font/local` ไฟล์ฟอนต์ commit ไว้ใน repo (Prompt และ IBM Plex Sans Thai ใช้สัญญาอนุญาต OFL ใส่ไฟล์ OFL ไว้ด้วย) เพื่อให้รันได้แม้เครื่องไม่มีอินเทอร์เน็ต |
| UI kit | Tailwind + shadcn/ui ใช้เฉพาะ Button, Input, Label, Textarea, Select, Switch, Card, Badge, Dialog, AlertDialog, Skeleton, Sonner · เก็บที่ `components/ui/` และไม่แก้ไฟล์ในโฟลเดอร์นี้นอกจาก variant ใน §6 · ให้ตรวจว่าคำสั่ง init ของ shadcn ใช้กับ Next.js 16 และ Tailwind ที่ติดตั้งได้ก่อนเริ่ม |
| วันที่ | `<input type="date">` ของเบราว์เซอร์ ไม่ใช้ปฏิทินสำเร็จรูป |

**ไฟล์ช่วยกลาง**

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/api-server.ts` | `apiGet<T>(path)` ฝั่งเซิร์ฟเวอร์ ส่งต่อ cookie แปลง problem+json เป็น error ที่มี `type`, `status`, `detail`, `errors` |
| `lib/api-client.ts` | `apiSend(method, path, body \| FormData)` ฝั่ง client · ถ้าเป็น `FormData` **ห้ามตั้ง `Content-Type` เอง** · ถ้า 401 พาไป login พร้อม `return_to` |
| `lib/time.ts` | format วันเวลาด้วย `Intl.DateTimeFormat('th-TH', { timeZone: 'Asia/Bangkok' })` (ปี พ.ศ. ตามค่าเริ่มต้นของ locale) · `toApiTime(date, 'HH:MM')` ประกอบสตริง `YYYY-MM-DDTHH:MM:00+07:00` เอง **ห้ามใช้ `toISOString()`** |
| `lib/problem.ts` | แปลง `type` เป็นข้อความไทยสำรอง กรณีเซิร์ฟเวอร์ไม่ส่ง `detail` |

## 3. แผนที่หน้า

| Route | อาร์ตบอร์ดอ้างอิง | Render | ใครเข้าได้ | ข้อมูลจาก |
|---|---|---|---|---|
| `/` | 1 รายการร้าน | Server + ช่องค้นหา Client | สาธารณะ | `GET /api/restaurants` (`sort`, `page`, `q`, `category` จาก `searchParams`), `GET /api/categories` |
| `/restaurants/[id]` | 2 รายละเอียดร้าน, 3 สถานะแผงจอง | Server + แผงจองและฟอร์มรีวิวเป็น Client | สาธารณะ | รายละเอียดร้าน, รีวิว, availability (ดึงฝั่ง client เมื่อเปลี่ยนวันที่) |
| `/bookings` | 4 การจองของฉัน, 8 หน้าต่างยืนยัน | Server + ปุ่มเป็น Client | login | `GET /api/me/bookings` |
| `/my/restaurants` | 5 ร้านของฉัน | Server | login | `GET /api/me/restaurants` |
| `/my/restaurants/new` | 6 ฟอร์มสร้างร้าน | Client | login | `POST /api/restaurants` |
| `/my/restaurants/[id]` | 7 จัดการร้าน, 8 หน้าต่างยืนยัน | Server + ส่วนโต้ตอบ | เจ้าของ | รายละเอียด, ตั้งค่า, รูป, พักรับจอง, ลบ |
| `/my/restaurants/[id]/edit` | 6 ฟอร์ม (โหมดแก้ไข) | Client | เจ้าของ | `PATCH /api/restaurants/{id}` |
| `/my/restaurants/[id]/bookings` | 7 (ส่วนการจองรายวัน) | Server | เจ้าของ (ระดับ B) | `GET /api/restaurants/{id}/bookings` · `?view=list` รายการทุกวันแบ่งหน้า (ค่าเริ่มต้น) · `?view=day&date=` รายวันพร้อม peak |
| `/auth/error` | — | Server | สาธารณะ | ข้อความตาม `code` |

ทุก route มี `loading.tsx`, `error.tsx` และ `not-found.tsx` · สถานะการค้นหาและการเรียงเก็บใน URL (แชร์ลิงก์และกดย้อนกลับได้) ช่องค้นหาหน่วงเวลา 300 ms ก่อนเปลี่ยน URL

## 4. พฤติกรรมที่ต้องตรงกับแบบ

**แผงจอง (หน้ารายละเอียดร้าน)**
- แสดงนโยบายร้านก่อนกดจอง (ยกเลิกได้ถึงกี่นาที, จองล่วงหน้าอย่างน้อยกี่ชั่วโมง, ครั้งละ 30 นาที–3 ชั่วโมง)
- ฟอร์ม: จำนวนคน, วันทำการ, เวลาเริ่ม, เวลาสิ้นสุด
- ตัวเลือกเวลาเริ่มมาจากช่องที่ `bookable` และ `remaining ≥ จำนวนคน` · ตัวเลือกเวลาสิ้นสุด +30 นาทีถึง +3 ชั่วโมง ตราบที่ทุกช่องระหว่างทางยังพอ
- ร้านข้ามเที่ยงคืน: ช่องหลังเที่ยงคืนติดป้าย "(วันถัดไป)"
- ตาราง 30 นาทีแสดง "ว่าง N ที่" · `limited` เป็นพื้นบัตเตอร์ "เหลือ N ที่" · ช่วงที่เลือกมีกรอบลาเวนเดอร์
- สรุปก่อนยืนยัน: วัน เวลา จำนวนคน ที่ว่างต่ำสุดในช่วงนั้น และ "ยกเลิกได้ถึง HH:mm"
- ได้ 409 หลังกดจอง: แสดง `detail` ของเซิร์ฟเวอร์ แล้วดึง availability ใหม่
- สถานะพิเศษตามอาร์ตบอร์ด 3: ยังไม่ login, ร้านพักรับจอง, เจ้าของร้าน (แทนแผงจองด้วยปุ่มจัดการร้าน), จองสำเร็จ (ใบจองพร้อมเลขที่)
- ปุ่มยืนยันปิดระหว่างรอผล (กันกดซ้ำ)

**รีวิว:** ดาว 1–5 เป็นปุ่มที่มี `aria-label` · ถ้ามี `my_review` แสดงเป็นโหมดแก้ไขพร้อมปุ่มลบ · รายการแบ่งหน้า

**การจองของฉัน:** แท็บ กำลังจะมาถึง / ผ่านไปแล้ว / ยกเลิกแล้ว ใช้พารามิเตอร์ `tab` ของ API และตัวเลขบนแท็บจาก `counts` (แท็บกำลังจะมาถึงเรียงจากใกล้สุดก่อน ซึ่งต่างจากลำดับในอาร์ตบอร์ด 4 ให้ยึดตาม API) · ไทล์วันที่ · ใช้ `can_modify`, `is_past`, `restaurant_deleted` จากเซิร์ฟเวอร์เท่านั้น · ยกเลิกผ่าน AlertDialog

**ฟอร์มร้าน:** 5 ส่วนมีเลขกำกับ · หมวดเลือกได้สูงสุด 3 · ตรวจรูปฝั่ง client ก่อนส่ง (ชนิดและ ≤ 2 MB) พร้อมพรีวิว · error `validation` แสดงใต้ช่องตาม `errors[].field`

**จัดการร้าน:** สถิติ 4 ช่อง, สวิตช์พักรับจอง, ตั้งค่าการจอง (409 แสดงรายการการจองที่ชน), ข้อมูลร้าน, รูป (ครบ 3 แล้วปิดการเพิ่ม), การจองรายวัน, ลบร้าน (409 แสดง `latest_booking_end` พร้อมปุ่มพักรับจอง)

## 5. Design Tokens — พาสเทลกระจก

**หลักสี:** สามสีพาสเทลห่างกันบนวงล้อ (พีช ≈ 17°, มิ้นต์ ≈ 153°, ลาเวนเดอร์ ≈ 252°) + บัตเตอร์ (≈ 46°) เสริมฝั่งอุ่น · ตัวอักษรเป็นม่วงน้ำเงินเข้มตระกูลเดียวกับลาเวนเดอร์ · สัดส่วน 60% กระจกขาวบนพื้นพาสเทล / 30% ลาเวนเดอร์ (ปุ่มหลัก, ตัวเลือกที่เลือก, หมวด) / 10% พีช (การกระทำสำคัญที่สุดของหน้า)

```css
:root {
  /* พื้นและตัวอักษร */
  --bg: #FBF9FF;
  --ink: #2B2550;          /* ตัวอักษรหลัก */
  --ink-2: #5D5880;        /* ตัวอักษรรอง */
  --ink-3: #6E6A8E;        /* hint, ไอคอน */
  --focus: #8C7CF0;        /* วงโฟกัส */
  --accent-strong: #6B5BD6;/* ตัวเลขใหญ่ คำเน้นในหัวข้อ */
  --star: #FFB547;

  /* พาสเทลพื้นหลัง */
  --peach: #FFD8C8; --lavender: #DED6FF; --mint: #CFF1E2; --butter: #FFF0BF;

  /* ปุ่ม (ไล่สีบนลงล่าง) */
  --btn-primary: #EFEAFF, #CFC4FF;            /* ตัวอักษร --ink */
  --btn-cta: #FFE9DF, #FFC2AA;                /* ตัวอักษร #3B1D12 */
  --btn-danger: #FFF0F3, #FFCCD6;             /* ตัวอักษร #8E1B33 */
  --btn-danger-strong: #FFE3E9, #FFA9BB;      /* ตัวอักษร #7A1029 */

  /* ป้ายสถานะ (พื้น / ตัวอักษร) */
  --st-mint: #D7F4E6 / #1E6B48;     /* ยืนยันแล้ว, เปิดรับจอง */
  --st-butter: #FFF1C2 / #7A5200;   /* เหลือน้อย, คำเตือน, หมดเวลาแก้ไข */
  --st-peach: #FFE2D6 / #9A3E22;    /* เจ้าของร้าน, รูปปก */
  --st-lav: #E7E1FF / #4A3DA8;      /* หมวดหมู่, ข้อมูล */
  --st-pink: #FFE0E7 / #A1203A;     /* ผิดพลาด, ลบ (ขอบ #FFC2CF) */
  --st-gray: #EEECF5 / #4B4766;     /* พักรับจอง, ยกเลิกแล้ว */
  --invalid: #D9506E;               /* ขอบช่องที่กรอกผิด */

  /* รูปทรง */
  --r-field: 14px; --r-btn: 16px; --r-card: 28px; --r-panel: 30px;
}
```
(บรรทัดที่มี `,` หรือ `/` ในค่าเป็นคำอธิบายคู่สี ให้แตกเป็นตัวแปรแยกตอนนำไปใช้จริง)

**พื้นหลังหน้า**
```css
background:
  radial-gradient(820px 520px at 6% -4%, #FFD8C8 0%, rgba(255,216,200,0) 62%),
  radial-gradient(860px 560px at 96% 0%, #DED6FF 0%, rgba(222,214,255,0) 60%),
  radial-gradient(760px 520px at 0% 70%, #CFF1E2 0%, rgba(207,241,226,0) 60%),
  radial-gradient(900px 600px at 100% 100%, #FFF0BF 0%, rgba(255,240,191,0) 60%),
  #FBF9FF;
```

**วัสดุกระจก**

| ชิ้น | สูตร |
|---|---|
| การ์ดและเมนูด้านบน | พื้น `rgba(255,255,255,0.58)` · ขอบ `1px rgba(255,255,255,0.92)` · เงา `0 14px 40px rgba(107,91,214,0.10)` + ไฮไลต์ `inset 0 1px 0 rgba(255,255,255,0.95)` · `backdrop-filter: blur(20px) saturate(160%)` |
| ปุ่ม | ขอบ `1px rgba(255,255,255,0.95)` · ไฮไลต์ `inset 0 1px 0 #fff` · เงาสีอ่อนตามสีปุ่ม · `backdrop-filter: blur(14px) saturate(170%)` · มุม 16px · สูงอย่างน้อย 48px (ปุ่มยืนยันการจอง 56–58px ตัวอักษร 18px หนา 700) |
| ช่องกรอก | พื้น `rgba(255,255,255,0.82)` · ขอบ `1px rgba(43,37,80,0.14)` · มุม 14px · สูง 48px · ผิด: ขอบ 2px `#D9506E` |
| ป้ายบนภาพ | พื้นขาว 86% + blur 8px + ตัวอักษร `--ink` (อ่านออกบนภาพจริงทุกโทน) |
| แถวในรายการยาว | พื้นขาว 70% **ไม่ใส่ blur** (ลดภาระการเรนเดอร์) |

**ตัวอักษร:** หัวข้อและปุ่มใช้ Prompt (500/600/700) · เนื้อหาใช้ IBM Plex Sans Thai (400/500/600) · เนื้อหา 16px line-height 1.55 · หัวข้อ line-height 1.15–1.25
**โฟกัส:** `:focus-visible { outline: 3px solid #8C7CF0; outline-offset: 2px }`
**Contrast:** ทุกคู่ตัวอักษร/พื้นข้างต้นตรวจแล้วผ่าน 4.5:1 · ปุ่มทุกแบบใช้ตัวอักษรเข้มเพราะพาสเทลรองรับตัวอักษรขาวไม่ได้

| `--cover-lilac` | `#EEE4FA → #D8C5EF → #C1AAE0` | สเต็กและกริลล์, อาหารเกาหลี |
| `--cover-sky` | `#E2EFFF → #C4DBFA → #ADC6F2` | อาหารญี่ปุ่น |

**การแมปกับตัวแปรของ shadcn/ui:** `--background` = `--bg` · `--foreground` = `--ink` · `--primary` = ลาเวนเดอร์ปุ่ม · `--primary-foreground` = `--ink` · `--muted-foreground` = `--ink-2` · `--destructive` = ชมพูปุ่ม · `--border` = `rgba(43,37,80,0.14)` · `--ring` = `--focus` · `--radius` = 16px

## 7. Design Decisions

| การตัดสินใจ | เหตุผล |
|---|---|
| Server Component อ่าน, Client Component ส่ง ไม่ใช้ Server Actions | กติกาอยู่ที่ Go ที่เดียว อธิบายง่าย และตรงหัวข้อสัมภาษณ์ (สไลด์ 13) |
| ไม่มี `proxy.ts` | เลี่ยงการตัด body เกิน 10 MB แบบเงียบ และการตรวจสิทธิ์ที่ proxy ไม่ควรเป็นด่านเดียว |
| สถานะค้นหาอยู่ใน URL | รีเฟรช ย้อนกลับ และแชร์ลิงก์ได้ |
| ฟอนต์แบบ local | รันได้แม้ไม่มีอินเทอร์เน็ต |
| ประกอบเวลาเป็นสตริง `+07:00` เอง | `toISOString()` แปลงเวลาตาม timezone ของเครื่องผู้ใช้ |
| แสดงปี พ.ศ. | เป็นธรรมชาติสำหรับผู้ใช้ไทย ส่วนค่าที่ส่ง API เป็นปีคริสต์เสมอ |
| พาสเทลกระจก, ตัวอักษรเข้มทุกปุ่ม | สดใสตามที่ต้องการ และยังผ่านเกณฑ์ contrast |
| blur เฉพาะเมนู แผง การ์ด และปุ่ม | `backdrop-filter` ใช้ทรัพยากรเครื่อง |

## 8. Definition of Done

- [ ] ทุก route ใน §3 ทำงานครบ flow ด้วยบัญชีทดสอบทั้ง 3
- [ ] หน้าตาตรงกับอาร์ตบอร์ดในระดับ layout, สี, ปุ่ม และสถานะ
- [ ] ไม่มี hydration warning เรื่องเวลา
- [ ] `loading`, `error`, `not-found` และ empty state ครบทุกหน้า
- [ ] ใช้งานด้วยคีย์บอร์ดได้ (โฟกัสมองเห็นชัด, Dialog ปิดด้วย Esc)
- [ ] responsive พอใช้บนจอมือถือ (ไม่ล้นแนวนอน)
