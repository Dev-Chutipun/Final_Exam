# DevPool Final Exam — ระบบจองโต๊ะร้านอาหารและรีวิวร้าน

[![CI](https://github.com/Dev-Chutipun/Final_Exam/actions/workflows/ci.yml/badge.svg)](https://github.com/Dev-Chutipun/Final_Exam/actions/workflows/ci.yml)

ผู้ใช้ทุกคนเป็นได้ทั้งลูกค้าและเจ้าของร้าน: สร้างร้าน (ชื่อ รายละเอียด รูป 1–3 รูป หมวด ที่นั่ง เวลาเปิด–ปิด) จองโต๊ะแบบนับที่นั่งเป็นช่วงเวลา 30 นาที แก้ไข/ยกเลิกก่อน deadline และรีวิวร้านของคนอื่น รายการร้านเรียงด้วยคะแนนแบบ Bayesian

| ส่วน | เทคโนโลยี |
|---|---|
| หน้าเว็บ | Next.js 16 (App Router, Turbopack), Tailwind CSS 4, shadcn/ui |
| API | Go 1.26 (`net/http` ServeMux, ไม่ใช้ framework), `pgx/v5` + SQL ที่เขียนเอง |
| ฐานข้อมูล | PostgreSQL 17 |
| Login | Keycloak 26.8 (OIDC) — Go เป็น confidential client แล้วสร้าง session ของแอปเอง |

```
browser ──► Next.js :3000 ──rewrite /api/*──► Go API :8080 ──► PostgreSQL :5432
                │ Server Component อ่านข้อมูล (ส่งต่อ cookie)        │
                └──────────────────────────────────────────────────► Keycloak :8081 (login)
```

สถาปัตยกรรม (quality attributes, C4, จุดยาก, 12-Factor, ทางโตระดับประเทศ) อยู่ที่ [docs/architecture.md](docs/architecture.md) และ ADR ใน [docs/adr/](docs/adr/)
· สเปก API ทั้ง 26 endpoint (OpenAPI 3.1) อยู่ที่ [docs/openapi.yaml](docs/openapi.yaml) เปิดดูได้ด้วย Swagger Editor หรือ `npx @redocly/cli preview-docs docs/openapi.yaml`
· บันทึกการพัฒนา (ลำดับงาน การตัดสินใจ ปัญหาที่เจอ ผลทดสอบ Checkpoint) อยู่ที่ [docs/dev-log.md](docs/dev-log.md)

## วิธีรันตั้งแต่ clone

**ต้องมี:** Git, Docker (Docker Desktop หรือ Rancher Desktop แบบ dockerd), Go 1.26.9 ขึ้นไป, Node.js 20.9 ขึ้นไป · พอร์ต 3000, 5432, 8080, 8081 ต้องว่าง

```powershell
git clone <repo> devpool; cd devpool
Copy-Item .env.example .env                       # ค่าสำหรับ Go (ใช้บนเครื่องเท่านั้น)
Copy-Item frontend/.env.example frontend/.env.local

docker compose up -d                              # postgres + keycloak (keycloak ใช้เวลาเริ่มราว 30 วินาที)

cd backend
go run ./cmd/migrate                              # สร้างตาราง (รันซ้ำได้)
go run ./cmd/seed                                 # ข้อมูลตัวอย่างอิงเวลาปัจจุบัน (-reset เพื่อล้างแล้วใส่ใหม่)
go run ./cmd/api                                  # API ที่ :8080 (ต้องรันบนเครื่อง ไม่รันใน Docker)

# อีกหน้าต่างหนึ่ง
cd frontend
npm ci
npm run dev                                       # เปิด http://localhost:3000
```

**หมายเหตุสำหรับ Windows**
- รันทุกคำสั่งใน **Windows PowerShell** ไม่ใช่ WSL/Ubuntu เพราะ `node_modules` ที่ติดตั้งจาก Windows ใช้ไบนารีของ Windows (รันใน WSL จะเจอ `Cannot find module '../lightningcss.linux-x64-gnu.node'`)
- ถ้าเครื่องปิดการรันสคริปต์ (`npm.ps1 cannot be loaded`) ใช้ `npm.cmd ci` / `npm.cmd run dev` และรันสคริปต์ด้วย `powershell -ExecutionPolicy Bypass -File .\scripts\test-race.ps1` หรือตั้งครั้งเดียว `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
- Docker บน WSL2 ต้องเปิด Virtualization (VT-x/AMD-V) ใน BIOS ไม่อย่างนั้น Docker Desktop/Rancher Desktop จะเริ่มไม่ได้

> Go ต้องรันบนเครื่องโดยตรง เพราะค่า `iss` ใน token ขึ้นกับ hostname ที่ใช้เรียก Keycloak: เบราว์เซอร์และ Go ต้องเรียก `localhost:8081` เหมือนกัน
> ถ้า Keycloak ยังไม่พร้อม `cmd/api` จะหยุดพร้อมข้อความ "ต่อ Keycloak ไม่ได้" ให้รอสักครู่แล้วรันใหม่

## วิธีรัน test

```powershell
cd backend
go test -p 1 ./...                 # test ทั้งหมดบน Windows (ต้อง docker compose up -d ก่อน ใช้ฐาน devpool_test)
cd ..
./scripts/test-race.ps1            # test ทั้งหมดแบบ -race ใน container golang
./scripts/test-race.ps1 -Concurrent   # เฉพาะ TestConcurrent* แบบ -count=100 -race

cd frontend
npm run lint                       # ESLint
npm run build                      # type check + build
```

- integration test ใช้ฐาน `TEST_DATABASE_URL` ถ้าไม่ได้ตั้งจะถูกข้าม · `-p 1` กันไม่ให้หลาย package ล้างฐานข้อมูลชนกัน
- ห้ามรัน `go test` บนเครื่องพร้อมกับ `test-race.ps1` เพราะใช้ฐาน test เดียวกัน
- หลังแก้ `.env` ใส่ `-count=1` เพื่อไม่ใช้ผลจาก cache

**CI** ([.github/workflows/ci.yml](.github/workflows/ci.yml)) รันทุก push และ pull request ที่เข้า `main` แบ่งเป็นสอง job ที่ทำงานขนานกัน

| job | ตรวจอะไร |
|---|---|
| Backend | `gofmt`, `go vet`, `go build`, `go test -p 1 -race ./...`, `TestConcurrent` แบบ `-count=100 -race`, `govulncheck` |
| Frontend | `npm ci`, ESLint, `tsc --noEmit`, `next build`, `npm audit --omit=dev` |

- ใช้ PostgreSQL 17 เป็น service container ตัวเดียว **ไม่ต้องมี Keycloak** เพราะ fake auth อยู่ใน `_test.go` และ test ของ auth ใช้ issuer ปลอม
- `-race` บน runner Linux รันตรง ๆ ได้ ไม่ต้องใช้ container แบบบน Windows
- มีขั้นตอนตรวจว่า integration test ได้คุยกับฐานข้อมูลจริง (นับแถวใน `schema_migrations`) กันกรณีที่ `TEST_DATABASE_URL` หลุดแล้ว test ถูกข้ามทั้งหมดแต่ CI ยังขึ้นเขียว

## Design Decisions

### การจอง ที่นั่ง และรีวิว

| การตัดสินใจ | เหตุผล | ที่มา |
|---|---|---|
| นับเป็นที่นั่ง ไม่แยกโต๊ะ | โจทย์กำหนด | สไลด์ 5 |
| ช่วงเวลาแบบ half-open `[start, end)` | จบกับเริ่มเวลาเดียวกันไม่ทับกัน ตรงกับตัวอย่างขวา | สไลด์ 7 |
| ตรวจ peak ไม่ใช่ผลรวมของการจองที่ทับ | ผลรวม (17) ให้คำตอบผิด peak (10) ให้คำตอบถูก | สไลด์ 7 |
| แก้ไขต้องตัดการจองเดิมออกก่อนเช็ค | ไม่นับที่นั่งเดิมซ้ำ | สไลด์ 8 |
| ล็อกแถวร้าน + Read Committed | การจองใหม่ยังไม่มีแถวให้ล็อก (phantom) จึงล็อกตัวแทนทรัพยากรคือร้าน | สไลด์ 11 |
| ไม่ใช้ exclusion constraint | กันได้แค่ห้ามทับ ไม่ใช่ผลรวมไม่เกิน | ออกแบบเอง |
| ช่องเวลา 30 นาที, จองได้ 30 นาที–3 ชม., ล่วงหน้าไม่เกิน 30 วัน | UI ง่าย กันการกักที่นั่งนานเกินไป และจำกัดขอบเขตข้อมูล | ตัดสินใจเอง |
| จองล่วงหน้าขั้นต่ำ ร้านตั้งเอง ค่าเริ่มต้น 2 ชม. และต้อง ≥ เวลายกเลิก | ร้านต่างประเภทต้องการเวลาเตรียมต่างกัน และกันการจองที่ยกเลิกไม่ได้ตั้งแต่ตอนสร้าง | ตัดสินใจเอง |
| ยกเลิกค่าเริ่มต้น 30 นาที ร้านตั้งนานขึ้นได้ ห้ามต่ำกว่า 30 | โจทย์กำหนด | สไลด์ 8 |
| บันทึก deadline ไว้ในการจองตั้งแต่ตอนจอง | นโยบายที่เปลี่ยนภายหลังไม่ย้อนหลังทำให้ลูกค้าเสียเปรียบ | ตัดสินใจเอง |
| แก้ไขใช้ deadline เดียวกับยกเลิก | กันการลดจำนวนคนนาทีสุดท้ายเพื่อเลี่ยงกติกายกเลิก | ตัดสินใจเอง |
| Deadline นับรวมเวลาพอดี | "ยกเลิกได้ถึง 11:30" | สไลด์ 8 |
| Owner จองร้านตัวเองไม่ได้ | บทบาทลูกค้าใช้กับร้านของคนอื่น | สไลด์ 3 |
| ห้ามผู้ใช้จองทับเวลาตัวเองในร้านเดียวกัน | กันการกักที่นั่งและการกดจองซ้ำ | ตัดสินใจเอง |
| Owner แก้ตั้งค่าไม่ได้ถ้าทำให้การจองเดิมผิดกติกา | กติกาต้องจริง "ไม่ว่าเวลาไหน" ไม่ใช่แค่ตอนจอง | สไลด์ 7 |
| แยก 409 / 422 | 409 ชนสถานะปัจจุบัน, 422 ผิดกติกาเสมอ | RFC 9110 |
| 1 คน 1 รีวิวต่อร้าน, ไม่ต้องเคยจอง, รีวิวร้านตัวเองไม่ได้ | กันปั่นคะแนน, โจทย์ห้ามเฉพาะรีวิวร้านตัวเอง | สไลด์ 9 |
| Owner ลบรีวิวในร้านตัวเองไม่ได้ | กันการลบรีวิวที่ไม่ชอบ ซึ่งทำลายความน่าเชื่อถือของคะแนน | ตัดสินใจเอง |
| คำนวณค่าเฉลี่ยตอนอ่าน | ข้อมูลเล็ก ความถูกต้องสำคัญกว่า มีแหล่งความจริงเดียว | สไลด์ 11 |
| เรียงด้วย Bayesian (C = 5, m สำรอง 3.0), ร้านไม่มีรีวิวอยู่ท้าย | 5.0 จาก 1 รีวิวไม่ควรชนะ 4.8 จาก 300 รีวิว | สไลด์ 11 |
| สถานะ "ผ่านไปแล้ว" คำนวณจากเวลา | ไม่ต้องมี cron job | ออกแบบเอง |
| Limited Seats Left เมื่อเหลือ ≤ 30% | ความหมายของ "เหลือ 3 ที่" ขึ้นกับขนาดร้าน | สไลด์ 10 |

### Login, session และ CSRF

| การตัดสินใจ | เหตุผล |
|---|---|
| Keycloak + session ของแอปเอง (Go เป็น OIDC client) | สมัครสมาชิกได้, token ไม่ถึง browser, ตอบได้ชัดว่า session เก็บที่ไหน |
| เก็บ hash ของ token ไม่เก็บค่าจริง | ฐานข้อมูลหลุดก็เอาไปใช้เป็น session ไม่ได้ |
| state + nonce + PKCE | กัน login CSRF, การใช้ token ซ้ำ และ code หลุด (RFC 9700 แนะนำ PKCE ทุก client) |
| ตรวจ `return_to` | กัน open redirect รวมกรณี `/\` |
| Logout ที่ Keycloak ด้วย และใช้ POST | สลับบัญชีได้จริง และเว็บอื่นสั่ง logout ไม่ได้ |
| ผูกผู้ใช้ด้วย `iss` + `sub` ไม่ใช้อีเมล | `sub` ไม่ซ้ำและไม่ถูกใช้ซ้ำภายใน issuer เดียวกัน ส่วนอีเมลเปลี่ยนได้ |
| ชื่อที่มี `@` ห้ามแสดง | กันอีเมลหลุดไปแสดงในรีวิว |
| Session 7 วัน | สะดวกตอนเดโม |
| CSRF 3 ชั้น | `SameSite`, ตรวจ origin, บังคับ JSON |
| Login ด้วย Google | ระดับ C ทำผ่าน Identity Provider ของ Keycloak ได้โดยไม่แก้โค้ด |

### จัดการร้าน รูป และหมวดหมู่

| การตัดสินใจ | เหตุผล |
|---|---|
| Owner เป็นความสัมพันธ์กับร้าน ไม่มี role | สไลด์ 3: ทุกคนสร้างร้านของตัวเองได้ |
| หมวดหมู่จากรายการกำหนดไว้ 1–3 หมวดต่อร้าน | กันคำซ้ำความหมาย ("ไทย", "อาหารไทย") และรองรับร้านที่อยู่หลายหมวด |
| ชื่อร้านไม่ซ้ำภายในเจ้าของคนเดียว (partial unique index) | กันการกดสร้างซ้ำโดยไม่ต้องมี Idempotency-Key และสร้างชื่อเดิมได้หลังลบ |
| รูปเก็บใน PostgreSQL (`bytea`) | สร้างร้านพร้อมรูปใน transaction เดียว ไม่มีไฟล์กำพร้า ไม่มี path traversal และกรรมการรันได้โดยไม่ต้องตั้ง volume |
| ตรวจชนิดรูปจากเนื้อไฟล์ ไม่รับ SVG | กันไฟล์ปลอมนามสกุลและสคริปต์ที่ฝังใน SVG |
| นับรูปหลังล็อกแถวร้าน | อัปโหลดพร้อมกันจะไม่เกิน 3 รูป |
| Soft delete และห้ามลบถ้ามีการจองในอนาคต | ประวัติลูกค้ายังอยู่ และลูกค้าไม่มาเจอร้านที่หายไป |
| พักรับจอง | ทางออกเมื่อร้านอยากเลิกกิจการแต่ยังมีการจองค้าง (Owner ยกเลิกการจองของลูกค้าเองไม่ได้) |
| แสดงเฉพาะชื่อลูกค้าให้ Owner | ไม่มีอีเมลในระบบตั้งแต่ส่วนที่ 2 |
| `ILIKE` แทน full-text search | ตัวแยกคำของ PostgreSQL ไม่ตัดคำภาษาไทย |

### หน้าเว็บ (Next.js)

| การตัดสินใจ | เหตุผล |
|---|---|
| Server Component อ่าน, Client Component ส่ง ไม่ใช้ Server Actions | กติกาอยู่ที่ Go ที่เดียว อธิบายง่าย และตรงหัวข้อสัมภาษณ์ (สไลด์ 13) |
| ไม่มี `proxy.ts` | เลี่ยงการตัด body เกิน 10 MB แบบเงียบ และการตรวจสิทธิ์ที่ proxy ไม่ควรเป็นด่านเดียว |
| สถานะค้นหาอยู่ใน URL | รีเฟรช ย้อนกลับ และแชร์ลิงก์ได้ |
| ฟอนต์แบบ local | รันได้แม้ไม่มีอินเทอร์เน็ต |
| ประกอบเวลาเป็นสตริง `+07:00` เอง | `toISOString()` แปลงเวลาตาม timezone ของเครื่องผู้ใช้ |
| แสดงปี พ.ศ. | เป็นธรรมชาติสำหรับผู้ใช้ไทย ส่วนค่าที่ส่ง API เป็นปีคริสต์เสมอ |
| พาสเทลกระจก, ตัวอักษรเข้มทุกปุ่ม | สดใสตามที่ต้องการ และยังผ่านเกณฑ์ contrast |
| blur เฉพาะเมนู แผง การ์ด และปุ่ม | `backdrop-filter` ใช้ทรัพยากรเครื่อง |
